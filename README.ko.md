# SAISENT 4.0

이 머신에서 지금 실행 중인 에이전트 세션에 미리 준비된 텍스트를 붙여 넣는 제어 패널입니다.

올바른 세션의 큐에 텍스트를 넣으면 — SAISENT가 에이전트 창을 활성화하고, 그 세션의 탭으로 전환하며, 텍스트를 한 번의 작업으로 붙여 넣고 Enter를 누릅니다.

## 빠른 시작

```
START_SAISENT.bat
```

Windows에서 Python 3.11+가 필요합니다.

## 사용 방법

1. **에이전트.** 맨 윗줄 — 체크박스: Claude Code, Freebuff, Antigravity, CodeNomad.
   에이전트를 체크하면 그 세션이 왼쪽 패널에 나타납니다.
2. **실시간 세션.** 왼쪽에는 실제로 실행 중인 것: 세션 이름, 탭 번호, 활동 센서, 프로젝트가 표시됩니다. "매 N초"를 켜지 않는 한 목록은 자동으로 갱신되지 않습니다 — 기본적으로 **새로고침** 버튼으로만 갱신됩니다.
3. **탭.** SAISENT는 세션 시작 순서로 탭 번호를 추측합니다. 틀렸다면? `SAISENT.json`의 `tabs` 키 아래에 번호를 직접 입력하세요(세션 키 형식 `<agent>:<id>`, 예: `{ "tabs": { "claude-code:abc123": 3 } }`). `0` = 탭을 전혀 전환하지 않음.
4. **텍스트.** 오른쪽 아래에 쓰거나(붙여 넣거나) **큐** (또는 Ctrl+Enter)를 누릅니다. **모두 큐에** 는 같은 텍스트를 모든 실시간 세션에 넣습니다 — 이전 "CTRL+2, 텍스트, CTRL+3, 텍스트" 매크로를 대체합니다.
5. **큐.** 행 순서 = 전송 순서. 행을 마우스로 끌거나 **위**/**아래** 버튼으로 이동합니다. 각 세션에는 자체 큐가 있습니다. 행을 더블클릭하거나(**편집** 버튼) 프롬프트를 텍스트 상자로 되돌립니다; **편집 저장** 은 제자리에 덮어쓰고, **취소** 는 버립니다. 이미 전송된 프롬프트를 편집하면 큐로 돌아갑니다 — 행의 텍스트는 더 이상 세션이 받은 것과 일치하지 않습니다. **복제** 는 바로 아래에 사본을 둡니다.
6. **전송.** **이 큐 보내기** — 선택한 세션만. **모두 보내기** — 모든 큐를 차례로. **드라이런** 은 아무것도 보내지 않고 로그에 계획만 표시합니다. 실제 전송은 먼저 확인을 요청하고 세션을 나열합니다.

## 전송 취소

전송 후 **실행 취소** 버튼이 30초간 표시됩니다. 마지막으로 보낸 프롬프트를 `pending` 상태로 큐에 되돌립니다 — 세션이 이미 처리하지 않은 경우(확인된 전달).

## 일정 및 제한

"보내기" 그룹에서:

- **보낼 시간 (HH:MM)** — 비어 있으면 "지금"입니다. 시간이 있으면 큐는 그 시간의 다음 도래(오늘, 이미 지났으면 내일)를 기다리고 상태 표시줄에 카운트다운을 표시합니다.
- **한도 초기화 대기** — 각 프롬프트 전에 SAISENT는 에이전트 자신의 텍스트를 읽습니다. "limit reached"라고 하면 큐는 기다렸다가 한도가 풀리면 자동으로 재개됩니다. 잠긴 문에 프롬프트를 하나도 보내지 않습니다.
- **한도 확인** — 지금 다시 스캔.
- 오른쪽의 상태 필드가 실시간 상태를 표시합니다: `limits: all agents free` 또는 `claude-code: LIMITED until 09:22 (1h 05m remaining)`, 빨간색. 카운트다운은 캐시에서 초당 한 번씩 흐릅니다. 디스크는 읽기가 오래되었거나 지정된 초기화 시간이 도래했을 때만 건드립니다.

초기화 시간은 에이전트 자신의 말에서 가져옵니다. 에이전트가 밝히지 않으면 SAISENT는 "+5시간" 같은 자리 표시자를 지어내는 대신 "reset time not stated"라고 씁니다.

### 제한이 초기화되는 시기

에이전트가 초기화 시간을 밝히지 않으면 SAISENT는 에이전트별 규칙에 의존합니다:

| 에이전트 | 규칙 | 의미 |
|---|---|---|
| Freebuff | `daily 10:00` | 매일 10:00에 초기화 |
| CodeNomad | `daily 03:00` | 매일 03:00에 초기화 |
| Claude Code | `rolling 5h` | 마지막으로 보낸 프롬프트 후 5시간 |
| Antigravity | 에이전트의 말만 | 규칙 없음 — 밝힌 것 또는 없음 |

규칙은 에이전트가 밝힌 시간을 절대 덮어쓰지 않습니다. 에이전트는 자신의 할당량에 대한 권위자입니다. `SAISENT.json`의 `quota_plans` 아래에서 규칙을 재정의할 수 있습니다(예: `{ "quota_plans": { "claude-code": "rolling 3h" } }`).

## 다음 것이 보내지지 않는 이유

전송은 엄격히 순차적이며 첫 번째 실제 오류에서 멈춥니다. 이유는 상태 표시줄(`stopped: window not found: ...`), 목록의 프롬프트 행, 로그에 표시됩니다. 나머지는 `pending`으로 남습니다 — 잃어버리지 않습니다.

프롬프트 사이에는 `gap_ms` 일시 중지(기본 1500ms)가 있고 상태는 `Waiting N.Ns before next`를 표시합니다. 프롬프트가 전송되었지만 세션이 움직이지 않으면 **미확인** 으로 표시되어 큐에 남습니다. "보냄"은 확인된 전달에만 적용됩니다.

## 활동 센서

"센서" 열은 "지금 입력할 수 있나요"에 답합니다.

- `busy` — 세션이 20초 미만 전에 저장소에 썼습니다(에이전트가 턴 중간에 있음);
- `idle` — 20초 이상 침묵, 입력 필드가 비어 있음.

어디서 오는지:

| 에이전트 | 출처 | 센서 |
|---|---|---|
| Claude Code | `~/.claude/sessions/<pid>.json` + 기록 | 기록의 마지막 쓰기 시간 |
| Freebuff | `<project>/.freebuff/desktop-v2.db`, `threads` 테이블 | `turn_state` 필드 |
| Antigravity | `~/.gemini/antigravity/conversations/*.db` | DB와 그 `-wal`의 mtime |
| CodeNomad | `~/.local/share/opencode/opencode.db` SQLite | 기록의 마지막 쓰기 시간 |

살아 있음은 별도의 검사이지 "디스크의 파일이 새것"이 아닙니다:

- **Claude Code** — `~/.claude/sessions/<pid>.json`의 PID가 살아 있습니다. 파일은 세션 종료 후에도 남습니다. PID는 아닙니다.
- **Freebuff** — `Freebuff.exe`가 실행 중입니다. DB는 앱이 종료된 후에도 스레드를 `open`으로 유지합니다.
- **Antigravity** — `Antigravity.exe`가 실행 중**이고** 대화가 새것입니다. 새것만으로는 부족합니다: 이 저장소는 모든 대화를 영원히 보관하며, 닫힌 편집기는 과거에 닿을 수 없는 세션으로 목록을 채웠습니다.
- **CodeNomad** — DB 행이 보관되지 않았습니다(`time_archived IS NULL`). 지금 열린 것만 활성입니다.

## 전달 주소 — "주소" 열

사이드바는 각 세션이 정확히 어떻게 맞을지 보여줍니다:

| 값 | 방법 | 신뢰성 |
|---|---|---|
| `cdp:28194` | 에이전트의 디버거를 통한 붙여넣기 | 정확: 전후에 필드를 읽고, 포커스를 훔치지 않음 |
| `CTRL+3` | 에이전트 창에서 탭 전환 | 탭 번호가 정확하면 좋음 |
| `blind` | 포트도 탭 번호도 없음 | 프롬프트는 열린 채팅에 떨어짐 |

창 제목에 세션 이름이 없습니다 — `claude.exe`는 "Claude", Antigravity는 "Antigravity", Freebuff는 "Freebuff Desktop"입니다. 따라서 창으로 주소를 지정하는 것은 불가능하며 `blind`는 말 그대로의 의미입니다.

### CDP — 신뢰할 수 있는 경로

에이전트가 `--remote-debugging-port`로 시작된 경우 SAISENT는 디버거를 통해 전송하며 포커스도 키보드도 건드리지 않습니다. 이는 다음을 의미합니다:

- 텍스트는 입력 필드에 직접 붙여 넣어지며 "아무 데나"가 아닙니다;
- 필드는 붙여넣기 **전에** 읽힙니다: 반쯤 쓴 메시지가 있으면 다른 사람의 문장에 덧붙이는 대신 전송을 거부합니다;
- 필드는 붙여넣기 **후에** 읽힙니다: 들어가지 않았다면 보내지 않습니다.

CDP 거부는 절대 눈먼 키 입력으로 되돌아가지 않습니다. 정밀한 전송 방식이 방금 순간이 잘못되었다고 말했습니다. 그 위에 키를 두드리는 것은 다른 사람의 채팅을 망치는 바로 그 방법입니다.

포트는 에이전트의 `DevToolsActivePort`에서 읽지만 파일만으로는 부족합니다 — 이전 실행에서 남은 것입니다. SAISENT는 각 프로브 전에 실제로 포트에 연결합니다.

에이전트용 디버거를 활성화합니다(재시작은 현재 작업을 죽입니다 — SAISENT는 스스로 절대 하지 않습니다):

```bash
"%LOCALAPPDATA%\Programs\Antigravity\Antigravity.exe" --remote-debugging-port=22998
```

### 페이지 선택자 (실제 DOM, 2026-08-05)

| 에이전트 | 포트 | 입력 필드 | 대화 목록 |
|---|---|---|---|
| Antigravity | `%APPDATA%\Antigravity\DevToolsActivePort` | `[aria-label="Message input"]` | `button[class*="headerbtn"]` |
| CodeNomad | `%APPDATA%\Plasticity\DevToolsActivePort` | `textarea.prompt-input` | `span.session-item-title` |
| Claude Code | `%APPDATA%\Claude\DevToolsActivePort` | — | — |
| Freebuff | 없음 | — | — |

Antigravity 검증됨: 16개 버튼, 레이블이 SAISENT가 표시하는 프로젝트 이름과 정확히 일치합니다(`_SAIPEN`, `_FastPrompter`, `SAISENT`, …) — 이름으로 대화 선택이 정확히 작동합니다.

CodeNomad는 OpenCode 위의 Electron입니다; 데이터 폴더는 여전히 `Plasticity`라고 합니다. DOM의 세션 목록에는 **현재 열린 프로젝트의** 세션만 포함됩니다. 다른 프로젝트의 세션은 렌더링되지 않으며 SAISENT는 찾지 못합니다 — 열린 채팅을 눈으로 치는 대신 전송을 거부합니다.

`SAISENT.json`에서 프로필 키를 재정의합니다:

```json
{ "cdp_profiles": { "codenomad": { "dialog_selector": ".session-list-item" } } }
```

## CodeNomad

세션은 `~/.local/share/opencode/opencode.db`의 `session` 테이블에서 읽습니다: 이름 = `title`, 프로젝트 = `directory`, 보관된 것은 `time_archived`로 필터링, 센서는 `time_updated`로. 세션 목록이 일반 열인 유일한 에이전트 — protobuf도 파싱도 없습니다.

살아 있음 — `CodeNomad.exe`가 실행 중입니다. 탭 번호 없음: 디버거를 통해 이름으로 주소를 지정합니다.

## 창 제목이 아닌 이유

모든 `claude.exe` 창은 "Claude"입니다. 세션 이름은 제목에 절대 나타나지 않으므로 창으로 주소를 지정하는 것은 불가능합니다 — 이름, 프로젝트, PID는 디스크에서 오고 창은 포커스에만 필요합니다.

## 전달 확인

Chromium은 `WM_GETTEXT`에 응답하지 않으므로 Win32를 통해 "들어갔는지"를 읽는 것은 불가능합니다 — 이 에이전트들에 대한 이전 read-back은 항상 "미확인"을 반환했습니다. 대신 SAISENT는 활동 센서가 지켜보는 동일한 파일이 움직이기를 기다립니다. 움직였다? 전달됨. 할당된 시간 안에 움직이지 않았다? 프롬프트는 전송되었지만 미확인으로 표시되며 로그에서 볼 수 있습니다. 오류로 간주되지 않습니다: 에이전트가 아직 턴을 시작하지 않았을 수 있습니다.

전송은 첫 번째 실제 오류에서 멈춥니다(창을 찾지 못함, 포커스 유실, 클립보드 사용 중). 후속 프롬프트는 큐에 남습니다 — 잃어버리지도 않고 눈으로 보내지도 않습니다.

## 내보내기 및 가져오기

**내보내기**와 **가져오기** 버튼은 큐를 JSONL 형식으로 저장/로드합니다. 각 행은 세션 키와 함께 자체 완결됩니다. 가져오기는 데이터 손실 없이 병합합니다 — 중복(같은 키 + 텍스트)은 건너뜁니다.

## 프로그램 옆의 파일

| 파일 | 내용 |
|---|---|
| `SAISENT.json` | 설정: 에이전트, 탭 번호, 제한 시간, 창 지오메트리 |
| `SAISENT_QUEUES.json` | 세션별 큐, 재시작 후에도 유지 |
| `SAISENT.log` | 전송 기록 |

큐는 절대 자동으로 정리되지 않습니다. 세션이 목록에서 사라졌지만 보내지 않은 항목이 있으면 큐는 유지됩니다: 에이전트는 다시 시작되며, 조용히 버려진 큐는 파일의 여분 행보다 더 나쁩니다.

## 숨겨진 설정

프로그램이 닫힌 상태에서 `SAISENT.json`을 편집합니다:

- `gap_ms` — 한 배치 내 프롬프트 사이의 일시 중지(기본 1500);
- `settle_ms` — 탭 전환 후 및 붙여넣기 후 일시 중지(400);
- `confirm_seconds` — 전달 확인을 기다리는 시간(10);
- `busy_seconds` — 센서 "busy/idle" 임계값(20);
- `freebuff_roots` — `.freebuff/desktop-v2.db`를 검색할 루트(예: `["V:\\___VAC\\__K\\__CODE"]`); 검색 깊이 3으로 제한;
- `submit` — 보내는 데 쓰는 키, 기본 `ENTER`.

## 제한 사항

- 탭은 `Ctrl+1..Ctrl+9`로 주소를 지정합니다. 열 번째 세션은 도달할 수 없습니다 — `Ctrl+10`은 존재하지 않으며 SAISENT는 추측 대신 거부합니다.
- 탭 번호는 시작 순서에 기반한 추측입니다. 첫 실행은 **드라이런**으로 하고, 그다음 중요하지 않은 세션에서 하세요.
- Antigravity는 대화 이름을 텍스트로 저장하지 않습니다: 목록은 메타데이터에서 추출한 작업 폴더 이름을 표시합니다.

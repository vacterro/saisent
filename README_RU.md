# SAISENT 4.0

Пульт, который вставляет заранее заготовленный текст в те сессии агентов,
которые прямо сейчас запущены на этой машине.

Ставишь текст в очередь нужной сессии — SAISENT активирует окно агента,
переключает таб этой сессии, вставляет текст одной операцией и жмёт Enter.

## Запуск

```
START_SAISENT.bat
```

Нужен Python 3.11+ для Windows.

## Как этим пользоваться

1. **Агенты.** Верхняя строка — галочки: Claude Code, Freebuff, Antigravity.
   Отмечаешь агента — его сессии появляются в списке слева. Комбобокса больше
   нет: агент либо опрашивается, либо нет.
2. **Живые сессии.** Слева список того, что реально работает: имя сессии, номер
   таба, датчик и проект. Список не обновляется сам, пока не включишь
   «каждые N с» — по умолчанию обновление только по кнопке **Обновить**.
3. **Таб.** Номер таба SAISENT угадывает по порядку запуска сессий. Если
   угадал не так — задай номер вручную в `SAISENT.json`, ключ `tabs`
   (ключ сессии вида `<агент>:<id>`, напр.
   `{ "tabs": { "claude-code:abc123": 3 } }`). `0` = не переключать таб
   вообще.
4. **Текст.** Пишешь (или вставляешь) внизу справа, жмёшь **В очередь**
   (или Ctrl+Enter). **В очередь всем** кладёт тот же текст каждой живой
   сессии — это замена старому макросу «CTRL+2, текст, CTRL+3, текст».
5. **Очередь.** Порядок строк = порядок отправки. Тащишь строку мышью или
   двигаешь кнопками **Выше**/**Ниже**. У каждой сессии своя очередь.
   Двойной клик по строке (или кнопка **Править**) вытаскивает промпт обратно
   в поле текста; **Сохранить правку** переписывает его на месте, **Отмена**
   бросает. Правка уже отправленного промпта возвращает его в очередь — текст
   в строке больше не тот, что получила сессия, и помечать его «ушло» было бы
   враньём. **Дублировать** кладёт копию сразу следом.
6. **Отправка.** **ОТПРАВИТЬ ЭТУ ОЧЕРЕДЬ** — только выбранная сессия.
   **ОТПРАВИТЬ ВСЕ** — все очереди подряд. **Пробный прогон** ничего не шлёт,
   а показывает план в журнале. Перед реальной отправкой спрашивает
   подтверждение и называет сессии.

## Расписание и лимиты

В группе «Отправка»:

- **Отправить в (HH:MM)** — пусто значит «сейчас». Со временем отправка ждёт
  ближайшего наступления этого времени (сегодня, а если уже прошло — завтра) и
  показывает обратный отсчёт в статусе.
- **Ждать сброса лимитов агента** — перед каждым промптом читается текст самого
  агента. Сказал «limit reached» — очередь держится и уходит сама, как только
  лимит снят; ни одного промпта в закрытую дверь.
- **Проверить лимиты** — перечитать прямо сейчас.
- Поле справа — живое состояние: `лимиты: все агенты свободны` либо
  `claude-code: ЛИМИТ до 09:22 (ещё 1ч 05м)`, красным. Отсчёт тикает раз в
  секунду из кэша; диск трогается только когда чтение устарело или когда
  названное время сброса наступило.

Время сброса берётся из слов агента. Не назвал — так и пишем
«время сброса не названо», а не подставляем выдуманные +5 часов.

## Почему следующие не отправляются

Отправка идёт строго по очереди и останавливается на первой настоящей ошибке.
Причина попадает и в статус (`остановлено: window not found: ...`), и в строку
промпта в списке, и в журнал. Остальные остаются `в очереди` — они не потеряны.

Между промптами держится пауза `gap_ms` (по умолчанию 1500 мс), и статус
показывает `Ждём N.Nс перед следующим`. Если промпт ушёл, но сессия не
шевельнулась, он считается **неподтверждённым**, остаётся в очереди, а в конце
пишется `готово, N не подтверждено — осталось в очереди`. «Ушло» ставится
только на подтверждённые.

## Датчик занятости

Столбец «Датчик» — не украшение, это ответ на вопрос «можно ли сейчас писать».

- `занята` — сессия писала в свой стор меньше 20 секунд назад, то есть агент
  в середине хода;
- `ждёт` — тишина дольше 20 секунд, поле ввода свободно.

Откуда берётся:

| Агент | Источник | Датчик |
|---|---|---|
| Claude Code | `~/.claude/sessions/<pid>.json` + транскрипт сессии | время последней записи в транскрипт |
| Freebuff | `<проект>/.freebuff/desktop-v2.db`, таблица `threads` | собственное поле `turn_state` |
| Antigravity | `~/.gemini/antigravity/conversations/*.db` | mtime базы и её `-wal` |

Живость — это отдельная проверка, а не «файл на диске свежий»:

- **Claude Code** — жив PID из `~/.claude/sessions/<pid>.json`. Файл после
  закрытия сессии остаётся, PID — нет.
- **Freebuff** — запущен `Freebuff.exe`. В базе поток остаётся `open` и после
  выхода из приложения.
- **Antigravity** — запущен `Antigravity.exe` **и** разговор свежий. Одной
  свежести мало: этот стор хранит все разговоры навсегда, и закрытый редактор
  раньше набивал список сессиями, до которых не долетит ни одна клавиша.

## Куда именно шлётся — столбец «Адрес»

В сайдбаре у каждой сессии написано, чем именно её будут бить:

| Значение | Что это | Насколько надёжно |
|---|---|---|
| `cdp:28194` | вставка через отладчик агента | точно: поле читается до и после, фокус не крадётся |
| `CTRL+3` | переключение таба в окне агента | нормально, если номер таба верный |
| `вслепую` | ни порта, ни номера таба | промпт уйдёт в тот чат, что сейчас открыт |

Ни один заголовок окна не содержит имени сессии — `claude.exe` называется
«Claude», Antigravity называется «Antigravity», Freebuff — «Freebuff Desktop».
Поэтому адресоваться по окну нельзя, и `вслепую` значит ровно то, что написано.

### CDP — надёжный путь

Если агент запущен с `--remote-debugging-port`, SAISENT шлёт через отладчик и
не трогает ни фокус, ни клавиатуру. Что это даёт:

- текст вставляется прямо в поле ввода, а не «куда попадёт»;
- поле читается **до** вставки: если там недописанное сообщение, отправка
  отказывается, а не дописывает в чужую фразу;
- поле читается **после** вставки: не долетело — не отправляем.

Отказ CDP никогда не откатывается на слепые клавиши. Точный транспорт только
что сказал, что момент неподходящий; долбить поверх этого клавишами — ровно тот
способ засрать чужой чат, ради которого всё и затевалось.

Порт берётся из `DevToolsActivePort` агента, но одного файла мало: он остаётся
от прошлого запуска. Перед каждой пробой SAISENT реально коннектится на порт.

Включить отладчик для агента (перезапуск убьёт то, что он сейчас делает —
SAISENT сам этого не делает никогда):

```bash
"%LOCALAPPDATA%\Programs\Antigravity\Antigravity.exe" --remote-debugging-port=22998
```

### Селекторы страниц (сняты с живого DOM 05.08.2026)

| Агент | Порт | Поле ввода | Список диалогов |
|---|---|---|---|
| Antigravity | `%APPDATA%\Antigravity\DevToolsActivePort` | `[aria-label="Message input"]` | `button[class*="headerbtn"]` |
| CodeNomad | `%APPDATA%\Plasticity\DevToolsActivePort` | `textarea.prompt-input` | `span.session-item-title` |
| Claude Code | `%APPDATA%\Claude\DevToolsActivePort` | — | — |
| Freebuff | нет | — | — |

Antigravity проверен: 16 кнопок, метки точно совпадают с именами проектов,
которые показывает SAISENT (`_SAIPEN`, `_FastPrompter`, `SAISENT`, ...) — выбор
диалога по имени работает точно.

CodeNomad — Electron поверх OpenCode, папка данных всё ещё зовётся
`Plasticity`. Список сессий в DOM содержит только сессии **текущего открытого
проекта**; сессия из другого проекта не отрендерена, и SAISENT её не найдёт —
отправка отказывается, а не бьёт наугад в открытый чат.

Freebuff слушает свой порт, но это не отладчик: `/json/list` отвечает
`401 Unauthorized`. Значит только `Ctrl+N` по табу.

Переопределить любой ключ профиля можно в `SAISENT.json`:

```json
{ "cdp_profiles": { "codenomad": { "dialog_selector": ".session-list-item" } } }
```

## CodeNomad

Сессии читаются из `~/.local/share/opencode/opencode.db`, таблица `session`:
имя = `title`, проект = `directory`, закрытые отсеяны по `time_archived`,
датчик — по `time_updated`. Единственный агент здесь, у которого список сессий
лежит обычными колонками, без протобуфа и без парсинга.

Живость — запущен `CodeNomad.exe`. Номера таба нет: адресуется по имени через
отладчик.

## Почему не по заголовку окна

Все окна `claude.exe` называются «Claude». Имя сессии в заголовок не попадает
вообще, поэтому адресоваться по окну нельзя — имя, проект и PID берутся с
диска, а окно нужно только чтобы получить фокус.

## Подтверждение доставки

Chromium не отвечает на `WM_GETTEXT`, поэтому прочитать «легло ли в поле» через
Win32 невозможно — старый read-back по этим агентам всегда возвращал
«не подтверждено». Вместо этого SAISENT ждёт, пока сдвинется тот же файл, по
которому работает датчик. Сдвинулся — доставлено. Не сдвинулся за отведённое
время — промпт помечается как отправленный, но неподтверждённый, и это видно
в журнале. Ошибкой это не считается: агент мог просто ещё не начать ход.

Отправка останавливается на первой настоящей ошибке (окно не нашлось, фокус
уехал, буфер обмена занят). Следующие промпты остаются в очереди — они не
теряются и не уходят вслепую.

## Файлы рядом с программой

| Файл | Что внутри |
|---|---|
| `SAISENT.json` | настройки: агенты, номера табов, паузы, геометрия окна |
| `SAISENT_QUEUES.json` | очереди по сессиям, переживают перезапуск |
| `SAISENT.log` | журнал отправок |

Очередь не чистится сама. Сессия пропала из списка, а в её очереди есть
неотправленное — очередь останется: агенты перезапускают, и тихо съеденная
очередь хуже лишней строки в файле.

## Настройки без интерфейса

Правятся в `SAISENT.json` (программа при этом должна быть закрыта):

- `gap_ms` — пауза между промптами внутри одной отправки (по умолчанию 1500);
- `settle_ms` — пауза после переключения таба и после вставки (400);
- `confirm_seconds` — сколько ждать подтверждения (10);
- `busy_seconds` — граница датчика «занята/ждёт» (20);
- `freebuff_roots` — корни, где искать `.freebuff/desktop-v2.db`, например
  `["V:\\___VAC\\__K\\__CODE"]`; поиск ограничен глубиной 3;
- `submit` — чем отправлять, по умолчанию `ENTER`.

## Ограничения

- Табы адресуются через `Ctrl+1..Ctrl+9`. Десятая сессия недоступна —
  `Ctrl+10` не существует, и SAISENT откажется, а не промахнётся.
- Номер таба — догадка по порядку запуска. Первый прогон делай с
  **Пробным прогоном**, потом на неважной сессии.
- Antigravity не хранит имя разговора текстом: в списке будет имя рабочей
  папки, вытащенное из метаданных.

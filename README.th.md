# SAISENT 4.0

แผงควบคุมที่วางข้อความที่เตรียมไว้ล่วงหน้าลงในเซสชันของเอเจนต์ที่กำลังทำงานอยู่บนเครื่องนี้

วางข้อความในคิวของเซสชันที่ถูกต้อง — SAISENT จะเปิดใช้งานหน้าต่างเอเจนต์ สลับไปยังแท็บของเซสชันนั้น วางข้อความในครั้งเดียว และกด Enter

## เริ่มต้นอย่างรวดเร็ว

```
START_SAISENT.bat
```

ต้องใช้ Python 3.11+ บน Windows

## วิธีใช้งาน

1. **เอเจนต์** แถวบนสุด — ช่องทำเครื่องหมาย: Claude Code, Freebuff, Antigravity, CodeNomad
   ทำเครื่องหมายเอเจนต์หนึ่งตัว เซสชันของมันจะปรากฏในแผงด้านซ้าย
2. **เซสชันสด** ด้านซ้ายคือสิ่งที่ทำงานจริง: ชื่อเซสชัน หมายเลขแท็บ เซนเซอร์กิจกรรม และโปรเจกต์ รายการจะไม่อัปเดตเอง เว้นแต่คุณจะเปิด "ทุก N วินาที" — โดยค่าเริ่มต้นจะอัปเดตด้วยปุ่ม **รีเฟรช** เท่านั้น
3. **แท็บ** SAISENT เดาหมายเลขแท็บจากลำดับการเริ่มเซสชัน ผิดไหม? พิมพ์หมายเลขด้วยตนเองใน `SAISENT.json` ภายใต้คีย์ `tabs` (คีย์เซสชันในรูปแบบ `<agent>:<id>` เช่น `{ "tabs": { "claude-code:abc123": 3 } }`) `0` = ไม่สลับแท็บเลย
4. **ข้อความ** พิมพ์ (หรือวาง) ด้านล่างขวา กด **เข้าคิว** (หรือ Ctrl+Enter) **ทั้งหมดเข้าคิว** วางข้อความเดียวกันในทุกเซสชันสด — แทนที่มาโครเก่า "CTRL+2, ข้อความ, CTRL+3, ข้อความ"
5. **คิว** ลำดับแถว = ลำดับการส่ง ลากแถวด้วยเมาส์หรือเลื่อนด้วย **ขึ้น**/**ลง** แต่ละเซสชันมีคิวของตัวเอง คลิกสองครั้งที่แถว (หรือปุ่ม **แก้ไข**) เพื่อดึงพรอมป์ต์กลับไปยังช่องข้อความ; **บันทึกการแก้ไข** เขียนทับในที่ **ยกเลิก** ทิ้ง การแก้ไขพรอมป์ต์ที่ส่งแล้วจะนำกลับเข้าคิว — ข้อความในแถวไม่ตรงกับสิ่งที่เซสชันได้รับอีกต่อไป **ทำสำเนา** วางสำเนาไว้ด้านล่างทันที
6. **การส่ง** **ส่งคิวนี้** — เฉพาะเซสชันที่เลือก **ส่งทั้งหมด** — ทุกคิวตามลำดับ **ทดลองแบบแห้ง** ไม่ส่งอะไร แสดงเพียงแผนในล็อก การส่งจริงจะขอการยืนยันก่อนและระบุเซสชัน

## เลิกทำการส่ง

หลังการส่ง ปุ่ม **เลิกทำ** จะปรากฏ 30 วินาที มันนำพรอมป์ต์ที่ส่งล่าสุดกลับเข้าคิวเป็น `pending` — เว้นแต่เซสชันจะประมวลผลแล้ว (การจัดส่งที่ยืนยันแล้ว)

## การกำหนดเวลาและขีดจำกัด

ในกลุ่ม "ส่ง":

- **ส่งเวลา (HH:MM)** — ว่างหมายถึง "ตอนนี้" เมื่อมีเวลา คิวจะรอการมาถึงครั้งถัดไปของเวลานั้น (วันนี้ หรือพรุ่งนี้หากผ่านไปแล้ว) และแสดงการนับถอยหลังในแถบสถานะ
- **รอการรีเซ็ตขีดจำกัด** — ก่อนแต่ละพรอมป์ต์ SAISENT อ่านข้อความของเอเจนต์เอง ถ้ามันบอกว่า "limit reached" คิวจะรอและดำเนินต่อโดยอัตโนมัติเมื่อขีดจำกัดว่าง ไม่มีพรอมป์ต์ใดชนประตูที่ล็อก
- **ตรวจสอบขีดจำกัด** — สแกนอีกครั้งทันที
- ช่องสถานะด้านขวาแสดงสถานะสด: `limits: all agents free` หรือ `claude-code: LIMITED until 09:22 (1h 05m remaining)` สีแดง การนับถอยหลังเดินทุกวินาทีจากแคช; ดิสก์จะถูกแตะเมื่อการอ่านเก่าหรือเมื่อถึงเวลารีเซ็ตที่ระบุเท่านั้น

เวลารีเซ็ตนำมาจากคำพูดของเอเจนต์เอง หากไม่ระบุ SAISENT จะเขียน "reset time not stated" แทนที่จะคิดค้นตัวยึดตำแหน่งเช่น "+5 ชั่วโมง"

### เมื่อไรขีดจำกัดจะรีเซ็ต

หากเอเจนต์ไม่เคยระบุเวลารีเซ็ต SAISENT จะใช้กฎต่อเอเจนต์:

| เอเจนต์ | กฎ | ความหมาย |
|---|---|---|
| Freebuff | `daily 10:00` | รีเซ็ตทุกวันเวลา 10:00 |
| CodeNomad | `daily 03:00` | รีเซ็ตทุกวันเวลา 03:00 |
| Claude Code | `rolling 5h` | 5 ชั่วโมงหลังพรอมป์ต์ที่ส่งล่าสุด |
| Antigravity | เฉพาะคำพูดของเอเจนต์ | ไม่มีกฎ — สิ่งที่มันระบุ หรือไม่มี |

กฎจะไม่ทับเวลาที่เอเจนต์ระบุเด็ดขาด; เอเจนต์คือผู้มีอำนาจเหนือโควตาของตัวเอง กฎใดๆ สามารถเขียนทับได้ใน `SAISENT.json` ภายใต้ `quota_plans` เช่น `{ "quota_plans": { "claude-code": "rolling 3h" } }`

## ทำไมรายการถัดไปจึงไม่ถูกส่ง

การส่งเป็นไปตามลำดับอย่างเคร่งครัดและหยุดที่ข้อผิดพลาดจริงครั้งแรก เหตุผลปรากฏในแถบสถานะ (`stopped: window not found: ...`) บนแถวพรอมป์ต์ในรายการ และในล็อก ที่เหลือยังคงเป็น `pending` — ไม่สูญหาย

ระหว่างพรอมป์ต์มีหยุดชั่วคราว `gap_ms` (ค่าเริ่มต้น 1500 มิลลิวินาที) และสถานะแสดง `Waiting N.Ns before next` หากพรอมป์ต์ถูกส่งแต่เซสชันไม่เคลื่อนไหว จะถูกทำเครื่องหมายว่า **ไม่ยืนยัน** และอยู่ในคิว "ส่งแล้ว" ใช้กับเฉพาะการจัดส่งที่ยืนยันแล้ว

## เซนเซอร์กิจกรรม

คอลัมน์ "เซนเซอร์" ตอบคำถาม "พิมพ์ตอนนี้ได้ไหม"

- `busy` — เซสชันเขียนไปยังที่เก็บน้อยกว่า 20 วินาทีที่แล้ว (เอเจนต์อยู่กลางเทิร์น);
- `idle` — เงียบเกิน 20 วินาที ช่องป้อนข้อมูลว่าง

มาจากไหน:

| เอเจนต์ | แหล่งที่มา | เซนเซอร์ |
|---|---|---|
| Claude Code | `~/.claude/sessions/<pid>.json` + บันทึกถอดความ | เวลาเขียนล่าสุดในบันทึกถอดความ |
| Freebuff | `<project>/.freebuff/desktop-v2.db` ตาราง `threads` | ฟิลด์ `turn_state` |
| Antigravity | `~/.gemini/antigravity/conversations/*.db` | mtime ของฐานข้อมูลและ `-wal` |
| CodeNomad | `~/.local/share/opencode/opencode.db` SQLite | เวลาเขียนล่าสุดในบันทึกถอดความ |

ความมีชีวิตเป็นการตรวจสอบแยก ไม่ใช่ "ไฟล์บนดิสก์สดใหม่":

- **Claude Code** — PID จาก `~/.claude/sessions/<pid>.json` ยังมีชีวิต ไฟล์อยู่รอดหลังปิดเซสชัน; PID ไม่รอด
- **Freebuff** — `Freebuff.exe` กำลังทำงาน ฐานข้อมูลรักษาเธรดให้ `open` แม้หลังออกจากแอป
- **Antigravity** — `Antigravity.exe` กำลังทำงาน **และ** การสนทนาสดใหม่ ความสดใหม่เพียงอย่างเดียวไม่พอ: ที่เก็บนี้เก็บการสนทนาทั้งหมดตลอดไป และโปรแกรมแก้ไขที่ปิดแล้วเคยเติมรายการด้วยเซสชันที่ไม่มีปุ่มใดเอื้อมถึง
- **CodeNomad** — แถวฐานข้อมูลไม่ได้เก็บถาวร (`time_archived IS NULL`) เฉพาะที่เปิดอยู่ตอนนี้เท่านั้นที่ทำงาน

## ที่อยู่การจัดส่ง — คอลัมน์ "ที่อยู่"

แถบด้านข้างแสดงว่าทุกเซสชันจะถูกจัดการอย่างไร:

| ค่า | วิธี | ความน่าเชื่อถือ |
|---|---|---|
| `cdp:28194` | วางผ่านดีบักเกอร์ของเอเจนต์ | แม่นยำ: อ่านช่องก่อนและหลัง ไม่ขโมยโฟกัส |
| `CTRL+3` | สลับแท็บในหน้าต่างเอเจนต์ | ดี ถ้าหมายเลขแท็บถูกต้อง |
| `blind` | ไม่มีพอร์ต ไม่มีหมายเลขแท็บ | พรอมป์ต์ตกลงในแชทที่เปิดอยู่ |

ไม่มีชื่อหน้าต่างใดมีชื่อเซสชัน — `claude.exe` เรียกว่า "Claude", Antigravity เรียกว่า "Antigravity", Freebuff เรียกว่า "Freebuff Desktop" การกำหนดที่อยู่ผ่านหน้าต่างจึงเป็นไปไม่ได้ และ `blind` หมายถึงสิ่งที่มันพูดอย่างแท้จริง

### CDP — เส้นทางที่เชื่อถือได้

หากเอเจนต์ถูกเริ่มด้วย `--remote-debugging-port` SAISENT จะส่งผ่านดีบักเกอร์และไม่แตะโฟกัสหรือคีย์บอร์ด หมายความว่า:

- ข้อความถูกวางลงในช่องป้อนข้อมูลโดยตรง ไม่ใช่ "ที่ไหนก็ได้";
- อ่านช่อง **ก่อน** วาง: หากมีข้อความที่เขียนครึ่งอยู่ การส่งจะปฏิเสธแทนที่จะต่อท้ายประโยคของผู้อื่น;
- อ่านช่อง **หลัง** วาง: หากไม่ลง เราไม่ส่ง

การปฏิเสธ CDP ไม่เคยตกไปที่การกดแป้นแบบสุ่มสี่สุ่มห้า ระบบขนส่งที่แม่นยำเพิ่งบอกว่าช่วงเวลานั้นผิด; การกดแป้นทับลงไปคือวิธีทำลายแชทของผู้อื่น

พอร์ตอ่านจาก `DevToolsActivePort` ของเอเจนต์ แต่ไฟล์เดียวไม่พอ — มันอยู่รอดจากการเริ่มครั้งก่อน SAISENT เชื่อมต่อกับพอร์ตจริงก่อนทุกการตรวจ

เปิดใช้งานดีบักเกอร์สำหรับเอเจนต์ (การรีสตาร์ทจะฆ่าสิ่งที่มันกำลังทำ — SAISENT ไม่เคยทำเอง):

```bash
"%LOCALAPPDATA%\Programs\Antigravity\Antigravity.exe" --remote-debugging-port=22998
```

### ตัวเลือกหน้า (DOM จริง, 2026-08-05)

| เอเจนต์ | พอร์ต | ช่องป้อนข้อมูล | รายการไดอะล็อก |
|---|---|---|---|
| Antigravity | `%APPDATA%\Antigravity\DevToolsActivePort` | `[aria-label="Message input"]` | `button[class*="headerbtn"]` |
| CodeNomad | `%APPDATA%\Plasticity\DevToolsActivePort` | `textarea.prompt-input` | `span.session-item-title` |
| Claude Code | `%APPDATA%\Claude\DevToolsActivePort` | — | — |
| Freebuff | ไม่มี | — | — |

Antigravity ผ่านการยืนยัน: 16 ปุ่ม ป้ายกำกับตรงกับชื่อโปรเจกต์ที่ SAISENT แสดงทุกตัว (`_SAIPEN`, `_FastPrompter`, `SAISENT`, …) — การเลือกไดอะล็อกด้วยชื่อทำงานแม่นยำ

CodeNomad คือ Electron บน OpenCode; โฟลเดอร์ข้อมูลยังเรียกว่า `Plasticity` รายการเซสชันใน DOM มีเฉพาะเซสชันของ **โปรเจกต์ที่เปิดอยู่ตอนนี้**; เซสชันจากโปรเจกต์อื่นไม่ถูกเรนเดอร์ และ SAISENT จะหามันไม่พบ — การส่งปฏิเสธแทนที่จะชนแชทที่เปิดอยู่โดยไม่รู้

เขียนทับคีย์โปรไฟล์ใดก็ได้ใน `SAISENT.json`:

```json
{ "cdp_profiles": { "codenomad": { "dialog_selector": ".session-list-item" } } }
```

## CodeNomad

เซสชันอ่านจาก `~/.local/share/opencode/opencode.db` ตาราง `session`: ชื่อ = `title`, โปรเจกต์ = `directory`, ที่เก็บถาวรกรองด้วย `time_archived`, เซนเซอร์ด้วย `time_updated` เอเจนต์เดียวที่นี่ที่รายการเซสชันเป็นคอลัมน์ธรรมดา — ไม่มี protobuf ไม่มีการแยกวิเคราะห์

ความมีชีวิต — `CodeNomad.exe` กำลังทำงาน ไม่มีหมายเลขแท็บ: กำหนดที่อยู่ด้วยชื่อผ่านดีบักเกอร์

## ทำไมไม่ใช้ชื่อหน้าต่าง

ทุกหน้าต่าง `claude.exe` เรียกว่า "Claude" ชื่อเซสชันไม่เคยปรากฏในชื่อเรื่อง ดังนั้นการกำหนดที่อยู่ผ่านหน้าต่างจึงเป็นไปไม่ได้ — ชื่อ โปรเจกต์ และ PID มาจากดิสก์; หน้าต่างจำเป็นสำหรับโฟกัสเท่านั้น

## การยืนยันการจัดส่ง

Chromium ไม่ตอบสนองต่อ `WM_GETTEXT` ดังนั้นการอ่าน "มันลงหรือยัง" ผ่าน Win32 จึงเป็นไปไม่ได้ — การอ่านกลับแบบเก่าสำหรับเอเจนต์เหล่านี้คืน "ไม่ยืนยัน" เสมอ แทนที่ SAISENT จะรอให้ไฟล์เดียวกับที่เซนเซอร์กิจกรรมเฝ้าดูเคลื่อนไหว เคลื่อนไหว? ส่งแล้ว ไม่เคลื่อนไหวภายในเวลาที่กำหนด? พรอมป์ต์ถูกทำเครื่องหมายว่าส่งแล้วแต่ไม่ยืนยัน และเห็นได้ในล็อก ไม่ถือเป็นข้อผิดพลาด: เอเจนต์อาจยังไม่ได้เริ่มเทิร์น

การส่งหยุดที่ข้อผิดพลาดจริงครั้งแรก (หาหน้าต่างไม่พบ โฟกัสหลุด คลิปบอร์ดไม่ว่าง) พรอมป์ต์ถัดไปยังคงอยู่ในคิว — ไม่สูญหายและไม่ถูกส่งแบบไม่รู้

## นำเข้าและส่งออก

ปุ่ม **ส่งออก** และ **นำเข้า** บันทึก/โหลดคิวในรูปแบบ JSONL แต่ละบรรทัดสมบูรณ์ในตัวเองด้วยคีย์เซสชัน การนำเข้าผสานโดยไม่สูญเสียข้อมูล — รายการซ้ำ (คีย์เดียวกัน + ข้อความ) จะถูกข้าม

| ไฟล์ | เนื้อหา |

| `SAISENT.json` | การตั้งค่า: เอเจนต์ หมายเลขแท็บ การหมดเวลา ขนาดหน้าต่าง |
| `SAISENT_QUEUES.json` | คิวต่อเซสชัน อยู่รอดการรีสตาร์ท |
| `SAISENT.log` | ล็อกประวัติการส่ง |

คิวไม่ถูกทำความสะอาดโดยอัตโนมัติ หากเซสชันหายจากรายการแต่มีรายการที่ยังไม่ส่ง คิวจะยังอยู่: เอเจนต์ถูกเริ่มใหม่ และคิวที่ถูกทิ้งอย่างเงียบๆ แย่กว่าบรรทัดพิเศษในไฟล์

## การตั้งค่าที่ซ่อน

แก้ไข `SAISENT.json` ในขณะที่โปรแกรมปิดอยู่:

- `gap_ms` — หยุดระหว่างพรอมป์ต์ในชุดเดียว (ค่าเริ่มต้น 1500);
- `settle_ms` — หยุดหลังสลับแท็บและหลังวาง (400);
- `confirm_seconds` — รอการยืนยันการจัดส่งนานเท่าไร (10);
- `busy_seconds` — เกณฑ์เซนเซอร์ "busy/idle" (20);
- `freebuff_roots` — รากที่ค้นหา `.freebuff/desktop-v2.db` เช่น `["V:\\___VAC\\__K\\__CODE"]`; ความลึกจำกัดที่ 3;
- `submit` — ปุ่มสำหรับส่ง ค่าเริ่มต้น `ENTER`

## ข้อจำกัด

- แท็บถูกกำหนดที่อยู่ผ่าน `Ctrl+1..Ctrl+9` เซสชันที่สิบไม่สามารถเข้าถึงได้ — `Ctrl+10` ไม่มี และ SAISENT ปฏิเสธแทนการเดา
- หมายเลขแท็บเป็นการเดาตามลำดับการเริ่ม ทำรอบแรกด้วย **ทดลองแบบแห้ง** จากนั้นในเซสชันที่ไม่สำคัญ
- Antigravity ไม่เก็บชื่อการสนทนาเป็นข้อความ: รายการแสดงชื่อโฟลเดอร์ทำงานที่ดึงจากเมตาดาตา
